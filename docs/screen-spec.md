# 叙光 Novel Studio：页面规格

## 页面名

今日工作台 + 五阶段创作工作区 + 多渠道模型配置抽屉。

## 页面目的

任何时刻回答：我在哪本书、当前做到哪、正在处理什么、下一步是什么；进入模型配置后，还要明确“有哪些 API 渠道、当前编辑哪个渠道、每个阶段实际走哪条模型路由”。

## 顶部状态

- 产品标识：叙光 Novel Studio。
- 项目：当前作品名，可切换。
- 对象：当前章或当前阶段。
- 阶段：Idea / 故事引擎 / 蓝图 / 写作 / 审查。
- 风险：阻塞数与过期状态。
- 下一步：在中央任务卡呈现，不在顶栏堆按钮。

## 左侧导航

- 今日
- Idea
- 故事引擎
- 小说蓝图
- 章节写作
- 审查定稿

左侧只做定位；阶段未解锁时显示原因，不伪装成可用。

## 中间主内容

- 顶部任务标题与简短说明。
- 当前产物编辑区或结构化表单。
- AI 建议与作者确认内容分开。
- 页面底部固定唯一主动作。

## 右侧检查器

- 当前作品指南针。
- 本阶段进入条件。
- 当前阶段模型路由是否完整。
- 风险与缺口。
- 最近一次模型运行的 API 渠道与模型。
- 上下游产物摘要。

## 模型配置抽屉

### 页面顺序

1. 顶部说明：密钥仅提交到本项目服务端。
2. API 服务渠道列表：显示渠道名、地址摘要、密钥状态，提供“添加渠道”。
3. 当前渠道编辑器：名称、Base URL、API Key、移除与测试。
4. 阶段路由表：每行只处理一个职责，包含 API 渠道选择和模型 ID。
5. 全局生成参数：温度、JSON 模式。
6. 底部：次动作“测试当前渠道”，唯一主动作“保存配置”。

### 主动作

保存全部 API 渠道与阶段路由。

### 空状态

没有渠道时展示“尚未添加 API 服务渠道”，唯一引导动作是添加第一个渠道；创作内容仍可保存。

### 阻塞状态

- 当前阶段未选择 API 渠道。
- 所选渠道缺 Base URL 或 API Key。
- 当前阶段缺模型 ID。
- 路由引用不存在的渠道。

阻塞只影响对应 AI 动作，不阻止作者编辑和保存 Workspace。

### 完成状态

保存后显示渠道数、已配置阶段数；创作页的进入条件和风险立即更新。

## 底部命令

不做常驻命令行。保存、导出、历史放入顶栏次级菜单。

## 主动作

随状态变化：生成建议 → 确认采用 → 进入下一阶段。

## 空状态

不用大面积空白或营销 Hero。展示一张“今天从这里开始”的任务卡和最少字段，主动作是建立作品或记录 Idea。

## 阻塞状态

模型路由未配置时，主动作显示“配置模型后继续”，点击后在本应用内打开配置抽屉；不跳转旧项目。

## 完成状态

展示简洁回执、下一阶段入口和本阶段确认摘要。

## 不展示

- 任一渠道的 API Key 原文。
- 旧项目链接。
- 原始文件树。
- 内部 Prompt 全文。
- 与当前任务无关的工具市场。

## v0.2：真实项目今日工作台页面规格

### 顶部状态

- 作品：真实项目名称；项目切换器列出扫描到的本地项目。
- 对象：当前章，例如“第 4 章”。
- 阶段：项目追踪账本中的当前阶段，例如“待正式草稿”。
- 风险：分别显示阻塞和提醒，不再把所有缺口都叫阻塞。

### 左侧导航（第一阶段过渡态）

- 今日工作台保持第一入口。
- 现有 Idea → 审查阶段仍作为“作品设计/候选稿流程”保留。
- 后续章节工作区完成后，左侧升级为“今日、章节、大纲、正式事实、诊断、运行记录”。

### 中间主内容

1. 今日任务标题：当前章节的命令式下一步。
2. 状态带：当前章、当前弧、章节契约、已完成章节。
3. 必须达成：来自 `追踪/今日工作台.md` 的当前章约束。
4. 今日清单：完成/待办任务。
5. 可用参考：章节契约、弧纲、规则和追踪账本。
6. 底部唯一主动作：开始写当前章或进入下一缺口。

### 右侧检查器

- 正式事实：项目来源、当前章、当前卷/弧。
- 风险：来自追踪账本的 P0/P1/提醒。
- 章节就绪度：章节契约、正文、追踪文件状态。
- AI 运行：仍读取独立 Workspace，不与正式事实混写。

### 空状态

只有没有发现真实项目时才显示“建立作品”的新书入口。

## v0.3：模型中心与章节校准台页面规格

### 左侧项目导航

真实项目模式下不再展示从 Idea 开书的五阶段导航，改为：

1. 今日工作台
2. 当前章工作区
3. 模型校准
4. 审查定稿（未接通时明确标注待开放）

### 模型配置抽屉

- 顶部先展示厂商预设卡，选择后创建厂商实例。
- 当前实例编辑区依次显示：厂商名称、协议、Base URL、API Key。
- API Key 字段说明必须使用“该厂商/中转服务提供的 Key”，不使用模型品牌误导用户。
- 阶段路由区显示职责、厂商和模型 ID；模型 ID 不承载密钥。
- 唯一主动作：保存配置；测试连接为次动作。

### 模型校准页

- 页头回答：正在校准哪本书、哪一章、用哪份契约。
- 左列：正式输入摘要（契约必达、禁区、P0 风险）。
- 右列：2—4 个候选槽，每槽选择厂商并填写模型 ID。
- 主动作：运行本章校准。
- 结果区：匿名候选卡并排，显示成功/失败、耗时、实际模型和输出；不默认宣布“最佳模型”。
- 空态明确提示：先在模型配置中填写各厂商自己的 API Key。

## v0.4：章节工作区与审查页规格

### 第 N 章工作区

- 页头显示候选状态、保存状态和最近一次实际模型路由。
- 契约摘要保持只读。
- 编辑器承载侧车候选正文，不复用新书 Workspace 的全局草稿。
- 次动作：先校准模型、手动保存。
- 唯一主动作按状态切换：生成候选 → 保存修改 → 进入审查。
- 未配置写作模型时，主动作打开模型配置抽屉并说明缺少哪一项。

### 审查定稿页

- 左侧或上部：只读候选正文摘要与版本信息。
- 主区：P0/P1/P2 Findings，必须包含证据、影响和抽象建议。
- 不展示模型代写的替换段落。
- 候选变化后显示“审查已过期”，主动作变为重新审查。
- 审查完成后唯一主动作是“确认当前候选版本”；确认后显示“等待差异预览与 checkpoint”。

### 项目导航

1. 今日工作台
2. 第 N 章工作区
3. 模型校准
4. 审查定稿

审查入口在候选稿为空时可见但禁用，并明确“先完成候选稿”。

## v0.5：写回预览页（Project Write-back Preview）

### 页面职责

只处理“已确认候选如何晋升为正式事实”。不编辑章节正文，不重新审查，不混入模型校准。

### 页面顺序

1. **顶部定位**：作品、章节、阶段“正式写回预览”、候选哈希短码、当前状态。
2. **安全闸门**：候选已确认、审查为当前版本、P0=0、正式正文目标不存在、同步提案状态。
3. **变更摘要**：新增 1 个正文文件、更新 N 个追踪文件、创建 1 个 checkpoint。
4. **文件差异列表**：按“正文 / 正式追踪 / 运行记录”分组；每项展示 action、路径、变化摘要、before/after 字符数和 source hash。
5. **展开检查器**：单个文件展开后展示 before 与 after；新增文件的 before 明确为“文件不存在”。
6. **最终确认区**：核对复选框、checkpoint 说明、唯一主动作。
7. **提交结果**：checkpoint ID、已写文件、回滚保护状态、下一章入口。

### 视觉层级

- `正文/` 使用最高正式事实权重，并标注“来自作者确认候选，模型未改写”。
- `追踪/` 为正式账本，次于正文但高于运行记录。
- `.data/writeback-checkpoints/` 只作为恢复点，使用中性灰层级。
- before/after 不默认铺满页面；先让作者扫描文件范围，再按需展开内容。

### 状态与文案

| 状态 | 顶部状态 | 唯一主动作 |
|---|---|---|
| blocked | 尚不满足写回条件 | 返回对应阶段 |
| empty | 尚未生成同步提案 | 生成追踪同步提案 |
| preparing | 正在提取追踪变化 | 正在生成… |
| ready | 差异已生成，正式文件未改动 | 创建 checkpoint 并正式写入 |
| stale | 候选或正式文件已变化 | 重新生成差异预览 |
| committing | checkpoint 与写入进行中 | 正在正式写入… |
| committed | 正式写入完成 | 进入下一章今日工作台 |
| error | 准备或提交失败 | 重试当前步骤 |

### 窄屏顺序

1. 当前状态与阻塞项。
2. 主动作。
3. 变更摘要。
4. 文件差异卡片。
5. 展开的 before/after。
6. checkpoint 和提交结果。

### 禁止项

- 不显示“模型直接同步正式文件”。
- 不把“生成提案”和“正式写入”放成两个并列主按钮。
- 不允许仅凭弹窗“确定”跳过文件差异核对。
- 不在正式写回页提供候选正文编辑器；要改正文必须回到候选稿并使审查/确认失效。

## v0.6：章节契约工作区

### 页面目的

回答四问：当前是第几章、正式契约是否存在、草稿还缺哪些硬结构、下一步是保存/预览/正式创建中的哪一步。

### 页面顺序

1. 顶部状态：书名、第 N 章、正式/侧车层级、契约状态。
2. 契约门禁：正式正文不存在、六个必需章节、正式目标路径。
3. 主编辑区：契约 Markdown；正式契约存在时切为只读。
4. 右侧/下方恢复包：今日主任务、硬规则、待推进伏笔、最近上下文摘要。
5. 差异预览：目标文件 before/after、hash、字符数；仅在计划存在时展示。
6. 底部唯一主动作：保存、预览、提交或进入候选正文。

### 状态文案

| 状态 | 顶部状态 | 唯一主动作 |
|---|---|---|
| formal | 正式契约已存在 | 进入候选正文 |
| empty | 尚未建立本章契约 | 保存章节契约草稿 |
| editing | 草稿有未保存修改 | 保存章节契约草稿 |
| saved_invalid | 草稿缺少硬结构 | 继续补齐契约 |
| saved | 侧车草稿已就绪 | 生成正式差异预览 |
| ready | 正式文件尚未改动 | 创建 checkpoint 并正式创建 |
| stale | 草稿或目标状态已变化 | 重新生成差异预览 |
| committed | 正式契约创建完成 | 进入候选正文 |

### 不展示

- 不把 `编译流/` 放在主编辑区。
- 不默认铺开所有正式上下文原文。
- 不提供任意文件路径输入。
- 不把“模型生成”和“正式写入”并列成两个主按钮。

## v0.7：候选正文生成预检

### 页面目的

在“按契约生成候选”与真实模型调用之间增加一个可见、可撤销的费用闸门，让作者知道本次调用的对象、输入、目标和落盘边界。

### 页面顺序

1. 候选页顶部：当前章、候选状态、写作路由简报。
2. 正式契约摘要：路径与只读预览。
3. 生成任务包（按需展开）：厂商、模型、章节 revision、必达目标、风险、输出层级。
4. 费用确认：明确说明会产生第三方费用，不展示密钥。
5. 候选编辑器：手写始终可用；模型输出只进入这里。
6. 底部唯一主动作：检查任务包、确认调用、保存或进入审查。

### 状态文案

| 状态 | 页面提示 | 唯一主动作 |
|---|---|---|
| no_candidate / gate_closed | 尚未核对本次模型任务 | 检查生成任务包 |
| gate_open / unacknowledged | 已展示路由与输入，费用待确认 | 禁用“确认调用” |
| gate_open / acknowledged | 本次调用边界已确认 | 确认调用模型生成候选 |
| generated | 模型候选已进入侧车 | 进入只读审查 |
| dirty | 当前候选有未保存修改 | 保存当前候选版本 |
| route_changed | 写作路由已变化 | 重新检查生成任务包 |

### 视觉层级

- 正式契约：绿色只读层。
- 生成任务包：蓝色运行层。
- 费用确认：琥珀色警示层。
- 候选正文：珊瑚色侧车层。
- 正式正文入口不在本页出现。

## v0.8：正文生成与质量门禁工作区

### 页面目的

围绕一条主路径回答：本章依据什么生成、当前候选是否通过硬检查、若未通过应重写哪里、通过后何时进入审查。token 与费用可在运行详情中查看，但不占首屏、不成为主动作。

### 页面顺序

1. 顶部状态：书名、第 N 章、`generating / candidate_ready / candidate_blocked / dirty / review_ready`、阻塞数和唯一下一步。
2. 输入任务包：正式事实清单、上一章正文、当前章正式契约；默认显示摘要、路径与 hash，可展开只读原文。
3. 章内节拍：按顺序展示场景目标、冲突/转折、情绪或爽点、字数预算和契约目标映射。
4. 完整候选正文：侧车编辑器；生成与重写结果都在这里形成完整版本。
5. 确定性质量门禁：通过项折叠，阻塞项置顶，并定位到对应节拍或正文位置。
6. 诊断区：门禁报告与只读审查 Finding 分栏，明确标记“诊断，不是正式事实”。
7. 底部固定唯一主动作；任务包、门禁明细、版本比较和运行元数据均为次级动作或检查器内容。

### 三层视觉

- 正式事实：绿色只读层，包含正式事实、上一章正式正文和正式章节契约。
- 侧车候选：珊瑚色工作层，包含任务包快照、章内节拍、完整候选和重写版本。
- 诊断：琥珀/红色检查层，包含确定性阻塞项和审查 Finding；不得与正式事实混排。

### 状态文案

| 状态 | 页面提示 | 唯一主动作 |
|---|---|---|
| `generating` | 正在按冻结任务包生成完整候选 | 正在生成… |
| `candidate_ready` | 候选已通过确定性质量门禁 | 进入只读审查 |
| `candidate_blocked` | 候选存在必须修复的硬问题 | 按阻塞项定向重写 |
| `dirty` | 节拍或候选有未保存修改，旧门禁已失效 | 保存并重新检查 |
| `review_ready` | 当前候选的审查结果已就绪 | 查看审查并决定 |

### 定向重写呈现

- 默认选中全部硬阻塞项，作者可取消非阻塞建议，但不能取消硬门禁。
- 重写范围显示关联节拍、正文位置和原因；不把 Prompt 全文暴露为编辑表单。
- 提交后页面进入 `generating`，保留当前候选只读快照；成功后以完整新版本替换工作副本并立即重跑门禁。
- 版本比较是次级动作，不与“定向重写”并列为主按钮。

### 不展示

- 不把 token、价格估算或厂商计费做成首屏 Hero、主状态或主按钮。
- 不出现“写入正式正文”“覆盖正文”等动作；生成和重写均只落侧车。
- 不把正式事实、候选建议和诊断 Finding 合并成同一种卡片。
- 不允许 `candidate_blocked` 直接进入审查，也不以模型自评替代确定性门禁。
- 不在同一页面并列“生成、重写、审查、正式写回”多个主动作。

## v0.9：开书工作台 / Idea 首屏

### 页面角色

- 回答“我在哪”：开书重建模式，作品为《苟成仙帝，出关即无敌》。
- 回答“现在怎样”：Idea 正在编辑，下游 4 个阶段尚未解锁。
- 回答“我在处理什么”：未经确认的作品承诺与原始矛盾。
- 回答“下一步做什么”：开始打磨 Idea，而不是写第 4 章。

### 页面顺序

`今日工作台（开书） → Idea → 故事引擎 → 小说蓝图 → 第 1 章写作 → 审查定稿`

### 首屏区块

1. 顶栏：作品名、对象“开书重建”、阶段“Idea”。
2. 左侧阶段导航：5 个产物阶段；Idea 可进入，其余按确认状态解锁。
3. 主区标题：从 Idea 重新打磨本书。
4. NEXT 卡：说明 Idea 本轮产物和进入条件。
5. 作品指南针：类型、读者、语气、模型渠道状态。
6. 右侧检查器：当前进入条件、风险、上/下游摘要。
7. 底部唯一主动作：开始打磨 Idea。

### 模式切换

- 作品切换器首项固定为“开书重建 · 从 Idea 开始”。
- 发现的本地正式项目显示为“续写已有正文”，并明确当前章号。
- 当前为续写模式时，可随时返回开书重建；该动作只切换视图与状态源，不修改文件。

### 空态与反馈

- 未配置模型：显示“尚未配置，不影响手动编辑”，主流程仍可保存作者输入。
- Idea 未填写：主动作不可直接调用模型，提示先补作品名与原始灵感。
- 磁盘中存在第 1-3 章：不在开书首屏强调，不自动跳到第 4 章。

## v1.0：Idea 打磨工作坊

### 页面角色

- 当前页不是一次性 AI 结果页，而是 Idea 的反复讨论与版本收敛工作坊。
- 页面优先回答：当前是第几版、这一版解决了什么、还要继续深挖什么、何时才值得定稿。

### 页面顺序

1. 当前工作稿：完整展示并允许逐字段编辑。
2. 本轮反馈：一个聚焦输入框，提示分别写“保留什么 / 推翻什么 / 继续深挖什么”。
3. 快速聚焦：金手指机制、闭关外爽点、主角动机、长线悬念、免费向开篇；点击只补充反馈，不立即调用模型。
4. 操作区：唯一主按钮“按反馈继续打磨一版”；旁边提供弱化的“确认当前版本为 Idea 定稿”。
5. 版本历史：默认折叠，显示版本号、来源、反馈摘要、时间和“恢复为当前工作稿”。

### 状态呈现

- `suggested`：显示“第 N 版工作稿”，反馈框可编辑。
- `generating`：当前稿保持可见但不覆盖，反馈框和按钮锁定，标题显示“正在生成第 N+1 版”。
- `error`：在操作区显示错误，当前稿和反馈原样保留，允许重试。
- `ready`：显示已定稿版本和确认时间；继续修改会使下游失效并回到打磨态。

### 主次动作

- 主动作仅有一个：继续打磨下一版。
- “确认当前版本”使用次级按钮，并明确说明确认后才会进入故事引擎。
- Idea 工作坊出现时隐藏全局底部确认条，防止误点即定稿。
- 版本恢复、复制反馈焦点、展开历史均为三级动作。

### 空态

- 尚无建议稿：沿用原始灵感输入与“生成第 1 版 Idea 建议”。
- 有旧建议但无历史：界面将其视为第 1 版；首次继续打磨时补齐历史记录。
